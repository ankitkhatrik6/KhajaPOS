# KhajaPOS Desktop App — Build Notes

This directory contains everything needed to rebuild the KhajaPOS **Desktop App
(Linux)** `.deb` package from the repository source.

The installable package is:

```
desktop/khajapos_2.2.0-1_all.deb      (native desktop app + local server)
```

## Package layout

```
DEBIAN/control        Package metadata and dependencies
DEBIAN/conffiles      /etc/khajapos/.env is a dpkg conffile
DEBIAN/postinst       First-install + upgrade setup:
                        - creates the 'khajapos' system user
                        - generates /etc/khajapos/.env, APP_KEY, DB_PASSWORD
                        - creates the restaurant_pos database and pos_user
                        - runs 'php artisan migrate --force'
                        - seeds demo data ONLY on an empty database
                        - enables and starts khajapos.service (auto-start at
                          boot) and refreshes the desktop menu/icon cache
DEBIAN/prerm          Stops the service before removal
DEBIAN/postrm         Purge: removes user, runtime dirs and the database
etc/khajapos/.env     Default configuration (conffile)
etc/logrotate.d/      Log rotation for /var/log/khajapos
opt/khajapos/         The complete application (Laravel 12 + vendor/) - this
                      directory is NOT stored in git, it is generated by
                      desktop/build-deb.sh from the repository root
usr/bin/khajapos      Control command (app, open, status, config, ...)
usr/bin/khajapos-app  Native desktop window (Python3 + GTK3 + WebKit2GTK):
                        - starts MariaDB + khajapos.service automatically
                        - loading screen while the server boots
                        - embedded KhajaPOS UI with menu bar, fullscreen/kiosk,
                          zoom and about dialog (browser fallback if no GUI)
usr/lib/systemd/system/khajapos.service
                      Runs: php artisan serve --host=0.0.0.0 --port=3000
usr/share/applications/khajapos.desktop
                      App menu entry + fullscreen/browser actions
usr/share/icons/hicolor/512x512/apps/khajapos.png
usr/share/pixmaps/khajapos.png
usr/share/doc/khajapos/README.md   In-package documentation
var/lib/khajapos/     Database backups directory
var/log/khajapos/     Application logs
```

## Rebuild from scratch

The whole flow is automated:

```bash
./desktop/build-deb.sh
```

This script:

1. rsyncs the current source tree (including `vendor/`) into
   `desktop/khajapos/opt/khajapos/`
2. copies the environment template (`desktop/khajapos/etc/khajapos/.env`)
   as `opt/khajapos/.env.package` (the packaged app uses this instead of `.env`)
3. refreshes the launcher icons from `public/logo.png`
4. builds `desktop/khajapos_2.2.0-1_all.deb` with root-owned files

### Sanity checks

```bash
dpkg-deb --info desktop/khajapos_2.2.0-1_all.deb
dpkg-deb --contents desktop/khajapos_2.2.0-1_all.deb | head
desktop-file-validate desktop/khajapos/usr/share/applications/khajapos.desktop
python3 -m py_compile desktop/khajapos/usr/bin/khajapos-app
bash -n desktop/khajapos/DEBIAN/postinst desktop/khajapos/DEBIAN/prerm \
       desktop/khajapos/DEBIAN/postrm desktop/khajapos/usr/bin/khajapos
```

## Install / test the build

```bash
sudo apt install ./desktop/khajapos_2.2.0-1_all.deb

# open the desktop app window
khajapos app

# open in the browser
khajapos open

# diagnose PHP, database and service
sudo khajapos doctor
```

Default admin login: `admin@khajapos.com` / `KhajaPOS@123`

## Automating releases

A GitHub Actions workflow (`.github/workflows/release-deb.yml`) builds the
package whenever a `v*` tag is pushed and attaches the `.deb` to the matching
GitHub Release, so every tag becomes a downloadable Linux build.
